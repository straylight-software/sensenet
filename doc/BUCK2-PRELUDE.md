# Buck2 Prelude Stack

This document describes sensenet's Buck2 toolchain rules - a complete, Nix-hermetic prelude stack that bypasses the standard Buck2 prelude for most languages.

## Overview

sensenet provides **custom Starlark toolchain rules** in `toolchains/*.bzl` that:

1. Read tool paths from `.buckconfig.local` (generated by `nix develop`)
2. Implement language-specific build logic directly
3. Produce outputs without depending on Buck2's language-specific prelude rules

The upstream Buck2 prelude (`nix/build/prelude/`) is used only for:
- Core infrastructure (`cmd_args`, `ctx.actions`, providers)
- C++ toolchain types (`CxxToolchainInfo`, `LinkerInfo`, etc.)
- Rust toolchain types (`RustToolchainInfo`)
- Haskell toolchain types (`HaskellToolchainInfo`)

## Language Details

### C++ (`cxx.bzl`)

**Rule:** `llvm_toolchain`

Uses LLVM 22 from the straylight fork with SM120 Blackwell support.

**Features:**
- Hermetic clang/clang++/lld from Nix store
- Automatic include path setup (glibc, gcc, clang resource dir)
- Automatic link path setup (rpath injection)
- C23 and C++23 support
- Static linking by default

**Config keys:**
```ini
[cxx]
cc = /nix/store/.../bin/clang
cxx = /nix/store/.../bin/clang++
ar = /nix/store/.../bin/llvm-ar
ld = /nix/store/.../bin/ld.lld
clang_resource_dir = /nix/store/.../lib/clang/22
gcc_include = /nix/store/.../include/c++/14
glibc_include = /nix/store/.../include
glibc_lib = /nix/store/.../lib
```

**Gaps:**
- No shared library support (static only)
- No cross-compilation
- No precompiled headers

### Haskell (`haskell.bzl`)

**Rules:** `haskell_toolchain`, `haskell_library`, `haskell_binary`, `haskell_c_library`, `haskell_ffi_binary`, `haskell_ffi_test`, `haskell_script`, `haskell_test`

Uses GHC 9.12 from nixpkgs with `ghcWithPackages`.

**Features:**
- GHC2024 language default
- Mandatory `-Wall -Werror`
- IDE support via `.hie` files (`-fwrite-ide-info`)
- Inter-package dependencies via `-i` flags
- FFI support (Haskell calling C++, C++ calling Haskell)
- Static libraries (`.a` archives)
- Package database from Nix

**Config keys:**
```ini
[haskell]
ghc = /nix/store/.../bin/ghc
ghc_pkg = /nix/store/.../bin/ghc-pkg
haddock = /nix/store/.../bin/haddock
global_package_db = /nix/store/.../lib/ghc-9.12.1/lib/package.conf.d
```

**Supported:**
- `haskell_library` - Compiles to `.hi/.o`, creates `.a` archive
- `haskell_binary` - Links executable
- `haskell_c_library` - FFI exports with stub header generation
- `haskell_ffi_binary` - Haskell main + C++ sources
- `haskell_ffi_test` - Test binaries with C++ FFI
- `haskell_script` - Single-file runghc scripts
- `haskell_test` - Test executables

**Gaps:**
- No Template Haskell cross-compilation
- No profiling builds
- No dynamic linking
- No Haddock documentation generation (haddock attr exists but unused)
- No GHCi support

---

### Rust (`rust.bzl`)

**Rules:** `rust_toolchain`, `rust_binary`, `rust_library`

Uses rustc from nixpkgs.

**Features:**
- Rust 2021 edition default
- Proc-macro support
- Feature flags
- Transitive dependency propagation
- Integration with `rust_crate.bzl` for crates.io deps

**Config keys:**
```ini
[rust]
rustc = /nix/store/.../bin/rustc
rustdoc = /nix/store/.../bin/rustdoc
clippy_driver = /nix/store/.../bin/clippy-driver
target_triple = x86_64-unknown-linux-gnu
```

**Gaps:**
- No incremental compilation
- No cargo build scripts (`build.rs`) - manual workarounds needed
- No workspace support
- No test targets
- No benchmark targets
- No cross-compilation

---

### Rust Crates (`rust_crate.bzl`)

**Rules:** `rust_crate`, `crates_io` (convenience macro)

Fetches and builds crates from crates.io.

**Features:**
- HTTP archive fetching with SHA256 verification
- Automatic `CARGO_PKG_*` environment variables
- Feature flag support
- Proc-macro support
- Generated file support for `build.rs` workarounds
- Wrapper script for `OUT_DIR` absolutization

**Example:**
```python
crates_io(
    name = "serde",
    version = "1.0.228",
    sha256 = "abc123...",
    features = ["serde_derive"],
    deps = [":serde_derive"],
)
```

**Gaps:**
- No automatic `build.rs` execution - must manually specify `generated_files`
- No automatic dependency resolution - must manually list deps
- No Cargo.lock parsing

### Lean 4 (`lean.bzl`)

**Rules:** `lean_library`, `lean_binary`, `lean_c_library`

Uses Lean 4 from nixpkgs.

**Features:**
- `.olean` compilation
- C code extraction (`--c` flag)
- C compilation and linking via leanc
- Dependency graph support
- Runtime library linking

**Config keys:**
```ini
[lean]
lean = /nix/store/.../bin/lean
leanc = /nix/store/.../bin/leanc
lean_lib_dir = /nix/store/.../lib/lean
lean_include_dir = /nix/store/.../include
```

**Gaps:**
- No Lake integration
- No Mathlib support (manual setup required)
- Limited multi-file project support
- No incremental olean updates

### NVIDIA/CUDA (`nv.bzl`)

**Rules:** `nv_toolchain`, `nv_binary`, `nv_library`

Uses clang for CUDA compilation (NOT nvcc).

**Features:**
- SM90/SM100/SM120 (Blackwell) support
- Pure clang compilation with `--cuda-path`
- PTX embedding for forward compatibility
- C++23 on device
- `std::mdspan` support

**Config keys:**
```ini
[nv]
nvidia_sdk_path = /nix/store/.../nvidia-sdk
nvidia_sdk_include = /nix/store/.../include
nvidia_sdk_lib = /nix/store/.../lib
ptxas = /nix/store/.../bin/ptxas
archs = sm_90,sm_100,sm_120
clang = /nix/store/.../bin/clang++
mdspan_include = /nix/store/.../include
```

**Gaps:**
- No cuBLAS/cuDNN integration (must manually add flags)
- No CUDA Fortran
- No texture/surface memory helpers
- No PTX assembly support

### PureScript (`purescript.bzl`)

**Rules:** `purescript_library`, `purescript_app`, `purescript_binary`

Uses purs + spago from purescript-overlay.

**Features:**
- Spago-based dependency management
- Halogen app bundling with esbuild
- Index.html and CSS injection

**Config keys:**
```ini
[purescript]

node = /nix/store/.../bin/node

```

**Gaps:**
- Network access required during build (spago fetches)
- No offline/hermetic builds
- No source maps
- No test targets

**Features:**

- Source bundling

**Gaps:**
- No pip/virtualenv integration
- No wheel building
- No type checking

### Nix Integration (`nix.bzl`, `nix_analyze.bzl`)

**Rules:** `nix_cxx_binary`, `nix_analyze`

Resolve Nix flake references to compiler flags.

**Features:**
- `nix_cxx_binary` - C++ binary with Nix deps
- `nix_analyze` - Resolve flake refs to include/link flags
- Automatic `-isystem`, `-L`, `-Wl,-rpath` injection

**Example:**
```python
nix_cxx_binary(
    name = "app",
    srcs = ["main.cpp"],
    nix_deps = ["nixpkgs#openssl", "nixpkgs#zlib"],
)
```

**Gaps:**
- Build-time nix evaluation (slow first build)
- No caching of nix resolution
- Limited to C++ (no Rust, Haskell nix deps)

## Architecture

```
.buckconfig
    |
    +-- [cells] prelude = nix/build/prelude (symlink to Nix store)
    +-- [cells] toolchains = toolchains
    |
    v
nix/build/prelude/                    toolchains/
(straylight fork of buck2-prelude)    (custom rules)
    |                                     |
    +-- cxx/cxx_toolchain_types.bzl       +-- cxx.bzl (llvm_toolchain)
    +-- rust/rust_toolchain.bzl           +-- rust.bzl (rust_*)
    +-- haskell/toolchain.bzl             +-- haskell.bzl (haskell_*)
    +-- ...                               +-- lean.bzl (lean_*)
                                          +-- nv.bzl (nv_*)
                                          +-- purescript.bzl (purescript_*)
                                          +-- rust_crate.bzl (crates_io)
```

## Configuration Flow

1. `nix develop` generates `.buckconfig.local` with Nix store paths
2. Buck2 reads `.buckconfig` which includes `.buckconfig.local`
3. Toolchain rules read paths via `read_root_config()`
4. Rules invoke tools at absolute Nix store paths

Example `.buckconfig.local`:
```ini
# Generated by nix develop - DO NOT EDIT

[cxx]
cc = /nix/store/abc123-llvm-22/bin/clang
cxx = /nix/store/abc123-llvm-22/bin/clang++
ar = /nix/store/abc123-llvm-22/bin/llvm-ar
ld = /nix/store/abc123-llvm-22/bin/ld.lld

[haskell]
ghc = /nix/store/def456-ghc-9.12/bin/ghc
ghc_pkg = /nix/store/def456-ghc-9.12/bin/ghc-pkg

[rust]
rustc = /nix/store/ghi789-rust/bin/rustc

[nv]
nvidia_sdk_path = /nix/store/jkl012-nvidia-sdk
archs = sm_90,sm_100,sm_120
```

## Known Issues

1. **Rust build.rs** - Crates with build scripts require manual `generated_files` specification
2. **Haskell TH** - Template Haskell works but cross-compilation untested
3. **PureScript** - Requires network for spago fetch
4. **Python** - Minimal support, not intended for general Python projects
5. **Go/Java** - Not supported, use standard prelude
