# sensenet Design Document

## Vision

**sensenet** is a pure Haskell build system that:
1. Reads typed Dhall configuration (`BUILD.dhall`)
2. Executes builds with content-addressed caching (DICE)
3. Optionally delegates to NativeLink for remote execution

The key insight: Dhall provides typed build configuration, Haskell provides the incremental computation engine, and NativeLink provides distributed execution.

### Problems

1. **Two code paths**: Dhall-based (`dhall-to-buck` + `to-starlark.dhall`) and Haskell-based (`SenseNet.Emit`). Neither is complete.

2. **Dead code**: TUI, Scheduler, Remote, Namespace modules are implemented but not wired to Main.

3. **Shelly dependency**: `Build.hs` uses Shelly for command execution. Should use typed-process or direct System.Process with proper error handling.

4. **Buck2 dependency ambiguity**: README says "no Buck2" but we generate BUCK files and shell out to buck2.

5. **No tests**: No test suite exists.

## Target Architecture

This branch builds the **native DICE path** - a pure Haskell build system independent of Buck2.
The Buck2 frontend path exists on other branches.

### Phase 1: Clean Foundation

**Goal**: Remove dead code, unify code paths, make `sensenet build` work standalone.

```
sensenet build //pkg:target
    │
    ├─► Discover BUILD.dhall files
    │
    ├─► Parse Dhall → IR.Package
    │
    ├─► Build dependency graph (IR → DICE.ActionGraph)
    │
    ├─► Execute actions (DICE.executeGraph)
    │   ├─► Check cache (content-addressed)
    │   ├─► Run compiler (typed-process)
    │   └─► Store results
    │
    └─► Report results
```

**Delete**:
- `SenseNet/Emit.hs` (use Dhall-side emission only)
- `SenseNet/Generate.hs`
- `SenseNet/Namespace.hs`
- `SenseNet/TUI.hs` (reintroduce later if needed)
- `SenseNet/Scheduler.hs` (reintroduce later)
- `SenseNet/Remote.hs` (reintroduce later)
- `SenseNet/CAS.hs`
- `NativeLink/` directory
- `Proto/` directory (60k lines of generated code)

**Keep and fix**:
- `Main.hs` - entry point
- `SenseNet/IR.hs` - typed representation
- `SenseNet/Dhall.hs` - parse BUILD.dhall
- `SenseNet/DICE.hs` - content-addressed caching
- `SenseNet/Build.hs` + `Build/*.hs` - execution
- `SenseNet/Toolchains.hs` - toolchain config
- `SenseNet/Discover.hs` - find packages

**Replace Shelly**:
Use `typed-process` for cleaner, typed subprocess handling:
```haskell
runCompiler :: [Text] -> IO (Either BuildError ())
runCompiler args = do
  (exitCode, stdout, stderr) <- readProcess (proc (head args) (map T.unpack $ tail args))
  case exitCode of
    ExitSuccess -> Right ()
    ExitFailure n -> Left $ CommandFailed (head args) n stderr
```

### Phase 2: Complete Native Build

**Goal**: Full native build execution without Buck2.

- Complete DICE implementation with proper invalidation
- All language builders working (C++, Rust, Haskell, Lean, PureScript)
- Parallel execution with memory awareness

### Phase 3: Advanced Features

**Goal**: Production-ready with remote execution.

- File watching for incremental rebuilds
- Remote execution via NativeLink
- TUI progress display
- Memory-aware scheduling

## Configuration

### BUILD.dhall Format

```dhall
let A = ../../../dhall/prelude/package.dhall

let myBinary = A.cxxBinary "hello" ["main.cpp"] []

in { targets = [ A.rule.cxxBinary myBinary ] }
```

### Toolchains

Read from `.buckconfig.local` (generated by `nix develop`):
```ini
[cxx]
cc = /nix/store/xxx/bin/clang
cxx = /nix/store/xxx/bin/clang++

[haskell]
ghc = /nix/store/yyy/bin/ghc
```

## Commands

| Command | Phase 1 | Phase 2 |
|---------|---------|---------|
| `sensenet build //pkg:target` | Native DICE | `buck2 build` |
| `sensenet targets` | List from Dhall | `buck2 targets` |
| `sensenet clean` | Remove sensenet-out | `buck2 clean` |
| `sensenet query` | - | `buck2 query` |

## Dependencies

### Minimal (Phase 1)
- `dhall` - parse BUILD.dhall
- `typed-process` - run compilers
- `cryptonite` - SHA256 for content addressing
- `aeson` - cache serialization
- `text`, `bytestring`, `containers` - standard

### Remove
- `shelly` - replace with typed-process
- `brick` - TUI not needed initially
- `proto-lens-*` - no gRPC needed without remote
- `grpc-haskell` - no gRPC needed
- `conduit` - not needed for simple IO

## Open Questions

1. **Buck2 or native?** 
   - Phase 2 (Buck2 frontend) is lower effort and production-ready sooner
   - Phase 3 (native) gives full control but is more work

2. **Remote execution?**
   - NativeLink integration was started but never completed
   - Could revisit after core is solid

3. **TUI?**
   - Nice to have but not essential
   - Could add back with better separation of concerns
